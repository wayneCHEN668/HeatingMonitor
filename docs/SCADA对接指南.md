## 1. 对接原则

1. **平台不直连 PLC。** 现场协议（OPC UA、Modbus TCP、IEC 60870-5-104、BACnet、厂家私有协议）由 SCADA 或采集网关负责。平台只和网关之间走 HTTPS 或 MQTT，用标准点位名交换数据。这样平台不依赖厂家位号，也不需要进入生产控制网络。
2. **采集和控制分通道。** 采集通道只读、数据量大，可以经单向网闸。控制通道写入、数据量小，必须双向认证、指令签名、回读确认。
3. **现场联锁保持不变。** 平台的安全校验（限值、变化率、频次、防冻联锁、仿真验证、审批令牌、熔断）是**额外的一层**，不替代 PLC 本地的限值保护、防冻和超温联锁。网关还应有自己的可写点位白名单和限值。
4. **以设备回读为准。** 指令只有在网关回读到设定值生效后才算执行成功。写入失败或超时不自动重试，以免重复写入；交由人工判断。
5. **通讯中断时现场保持当前设定。** 这与平台熔断的行为一致：熔断只收回自动化权限，不改变现场设定，不自动停热。
6. **时间统一。** 所有时间带时区（ISO 8601，如 `2026-11-03T10:00:00+08:00`），使用现场采样时间而不是接收时间；网关与平台都需 NTP 校时，误差不超过 1 秒。

## 2. 对接架构

```
 生产控制网络（OT）                             │  管理信息网络（IT）
                                               │
 热力站 PLC ─┐                                  │
 热源 DCS  ──┼─ OPC UA / Modbus / IEC 104 ─► SCADA / 采集网关 ─┬─ 采集通道（HTTPS 或 MQTT，经单向网闸可选）─► 平台 /api/ingest/*
 室温采集器 ─┘                                  │              │
 （或物联网平台）                                │              └◄─ 控制通道（HTTPS + mTLS + 指令签名）◄─ 平台安全网关
                                               │
                                               │   平台：实时库 → 报警判定 → 统计/AI → 调控链路
```

**控制通道的两种连接方式**，按网络安全策略二选一：

| 方式 | 说明 | 适用 |
|---|---|---|
| 推送（平台 → 网关） | 平台安全网关调用网关的 `POST /commands` | IT 侧允许主动连接 OT 侧网关 |
| 拉取（网关 → 平台） | 网关定期轮询平台 `GET /api/ingest/commands/pending` 取待执行指令，执行后回调结果 | 只允许 OT 侧向外发起连接（常见） |

**采集通道**也可以用 MQTT 代替 HTTPS，主题建议如下，QoS 1、TLS、按网关划分 ACL：

| 主题 | 方向 | 内容 |
|---|---|---|
| `heatnet/{gateway_id}/rt` | 网关 → 平台 | 实时数据，格式同 4.1 |
| `heatnet/{gateway_id}/evt` | 网关 → 平台 | 设备报警与事件，格式同 4.3 |
| `heatnet/{gateway_id}/hb` | 网关 → 平台 | 心跳，格式同 4.4 |
| `heatnet/{gateway_id}/cmd` | 平台 → 网关 | 控制指令，格式同 5.1 |
| `heatnet/{gateway_id}/cmd_result` | 网关 → 平台 | 指令结果，格式同 4.5 |

**数据量估算**：本演示规模为 3 个热源、13 个热力站，每站约 40 个点，热源约 100 个点，总计约 800 点，每 2–5 秒一次，HTTPS 批量上报足够。城市规模按 500 个站 × 50 点 / 5 秒估算，约 5000 点/秒，需要用 MQTT 或批量压缩，并使用时序数据库。

## 3. 标准点表（物模型）

点位名统一为 `{对象ID}.{指标}`，例如 `ST07.ts2`。对象 ID 与平台台账一致：热源 `HSxx`、热力站 `STxx`。现场位号与标准点位的对应关系由点表维护（见 4.6），网关负责单位换算。

表中未标注的指标与平台当前实时快照的字段名一致（`backend/app/sim/realtime.py` 中 `tick()` 和 `_source_snapshot()` 生成的字段），接入真实数据后保持这些字段名不变，前端、统计、AI、报告就不需要修改。标注 **新增** 的是对接需要、而当前快照中没有的点位（仿真器不需要它们，例如远程/就地状态、表计累计值），实现对接时要在实时库中补上。

### 3.1 热力站：采集点

| 指标 | 名称 | 单位 | 必需 | 来源与说明 |
|---|---|---|---|---|
| `ts1` / `tr1` | 一次供水 / 回水温度 | ℃ | 必需 | 一次侧温度变送器 |
| `p1s` / `p1r` | 一次供水 / 回水压力 | MPa | 必需 | 压力变送器；资用压差 = p1s − p1r |

| `heat_gj_total` **新增** | 累计热量 | GJ | 建议 | 热量表累计值，用于小时热量与能耗统计（平台按差值计算） |
| `ts2` / `tr2` | 二次供水 / 回水温度 | ℃ | 必需 | |
| `p2s` / `p2r` | 二次供水 / 回水压力 | MPa | 必需 | |
| `g2` | 二次流量 | t/h | 建议 | |
| `valve` | 调节阀开度反馈 | % | 必需 | 阀位反馈，不是设定值 |
| `pump_freq` | 循环泵运行频率 | Hz | 必需 | 变频器反馈 |
| `pump_kw` | 循环泵功率 | kW | 建议 | |
| `pump_run` **新增** | 循环泵运行状态 | 0/1（每台一个） | 必需 | |
| `makeup_tph` | 补水流量 | t/h | 必需 | 失水报警依据 |

### 3.2 热力站：控制点（可写，每个都要有回读）

当前快照里只有这些设定的回读值（`mode`、`ts2_set`、`valve_set`、`pump_freq`），调控链路直接修改仿真器内部状态。对接时需要新增下表的可写点位，并让 `ControlService` 通过网关写入。

| 指标 | 名称 | 单位 / 取值 | 平台限值（`backend/app/config.py` 中的 `LIMITS`） |
|---|---|---|---|
| `mode` | 控制模式 | `curve` 气候补偿 / `fixed` 定供温 / `manual` 手动阀位 | — |
| `curve` **新增** | 气候补偿曲线 | 8 个点：室外温度 −26、−20、−15、−10、−5、0、5、10 ℃ 对应的二次供温 | 单点单次调整 ≤ 8 ℃；单调递减；散热器系统 28–75 ℃，地暖 25–50 ℃ |
| `ts2_sp` **新增** | 二次供温设定（定供温模式） | ℃ | 单次调整 ≤ 5 ℃ |
| `valve_sp` **新增** | 调节阀开度设定（手动模式） | % | 5–100 %，单次 ≤ 20 %；室外低于 −10 ℃ 时不低于 15 % |
| `pump_freq_sp` **新增** | 循环泵频率设定 | Hz | 30–50 Hz，单次 ≤ 5 Hz |
| `ts2_set` | 当前二次供温目标（只读） | ℃ | 气候补偿模式下由 PLC 按曲线算出，回读用 |

> 真实系统中气候补偿曲线由热力站 PLC 本地执行，平台只写曲线参数或设定值。仿真器里这部分由平台的实时引擎模拟。如果现场控制器只支持“曲线平移量”或“斜率+截距”而不支持 8 点曲线，需要在网关或平台侧做换算，并在点表中注明。

## 4. 平台需要提供的接口（采集网关调用）

基础约定：

- 基础路径 `https://{平台}/api/ingest`。
- 认证：每个网关一个服务账号，使用双向 TLS 客户端证书，或 `Authorization: Bearer {网关令牌}`。需要新增权限 `ingest:write`，只授予网关服务账号，人工和智能体都不能有。
- 每个网关只能写入其负责的对象，由点表中的 `gateway_id` 约束。
- 返回统一封套：`{ok, summary, data, error?, trace_id}`。
- 幂等：同一 `gateway_id` + `seq` 重复上报只处理一次。

### 4.1 实时数据上报 `POST /api/ingest/realtime`

建议每 2–5 秒一批（平台实时引擎 2 秒一拍），每批不超过 5000 个点。

```json
{
  "gateway_id": "GW-HS02-01",
  "seq": 1024,
  "sent_at": "2026-11-03T10:00:02+08:00",
  "points": [
    {"tag": "ST07.ts2", "value": 41.7, "ts": "2026-11-03T10:00:00+08:00", "quality": "good"},
    {"tag": "ST07.makeup_tph", "value": 1.41, "ts": "2026-11-03T10:00:00+08:00", "quality": "good"},
    {"tag": "ST07.tin", "value": 20.4, "ts": "2026-11-03T09:55:00+08:00", "quality": "stale"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `tag` | 标准点位名；也可以上报现场位号，由平台按点表转换（二选一，需在点表中约定） |
| `value` | 数值；开关量用 0/1；模式等枚举用字符串 |
| `ts` | 现场采样时间 |
| `quality` | `good` 正常 / `uncertain` 可疑 / `bad` 坏值 / `stale` 超时未更新。`bad` 和 `stale` 平台按缺失处理，计入熔断的数据缺失率 |

响应：

```json
{"ok": true, "summary": "接收 118 个点，拒绝 2 个",
 "data": {"accepted": 118,
          "rejected": [{"tag": "ST07.foo", "reason": "未知点位"},
                       {"tag": "ST01.ts2", "reason": "不属于该网关负责的对象"}],
          "server_time": "2026-11-03T10:00:02.315+08:00"},
 "trace_id": "a1b2c3d4e5f6"}
```

`server_time` 供网关检查时钟偏差。

### 4.2 历史补传 `POST /api/ingest/history`

通讯恢复后补传中断期间的数据，或首次接入时导入历史（建议至少一个完整采暖季，供负荷预测、异常检测和节能基准使用）。

```json
{
  "gateway_id": "GW-HS02-01",
  "resolution": "raw",
  "points": [
    {"tag": "ST07.ts2", "values": [[ "2026-11-03T08:00:00+08:00", 41.2, "good" ],
                                    [ "2026-11-03T08:00:05+08:00", 41.3, "good" ]]}
  ]
}
```

`resolution` 为 `raw`（原始采样）或 `hour`（小时均值；累计量为小时增量）。补传数据只入历史库，不触发实时报警。

### 4.3 设备报警与事件上报 `POST /api/ingest/events`

PLC 或 SCADA 自身产生的报警、事件顺序记录（SOE），例如泵故障、超温联锁动作、就地/远程切换、门禁。

```json
{
  "gateway_id": "GW-HS02-01",
  "events": [
    {"event_id": "GW-HS02-01-88231", "object_id": "ST07", "code": "PUMP1_FAULT", "level": 1,
     "message": "1#循环泵变频器故障", "state": "raise", "ts": "2026-11-03T09:58:12+08:00"},
    {"event_id": "GW-HS02-01-88232", "object_id": "ST07", "code": "LOCAL_MODE", "level": 3,
     "message": "切换为就地控制", "state": "raise", "ts": "2026-11-03T09:58:40+08:00"}
  ]
}
```

`state` 为 `raise` 发生 / `clear` 恢复。`level` 为 1–3 级，与平台报警等级一致。平台把它们与自身的报警判定（补水异常、室温偏低、热量偏差等）合并显示，`event_id` 用于去重。

### 4.4 网关心跳 `POST /api/ingest/heartbeat`

每 10 秒一次。连续 3 次收不到心跳，平台把该网关负责的所有对象判为通讯中断。

```json
{
  "gateway_id": "GW-HS02-01",
  "ts": "2026-11-03T10:00:00+08:00",
  "version": "2.4.1",
  "links": [
    {"object_id": "ST07", "online": true, "last_seen": "2026-11-03T09:59:58+08:00", "remote": true},
    {"object_id": "ST10", "online": false, "last_seen": "2026-11-03T09:41:02+08:00", "remote": true}
  ],
  "queue": {"pending_points": 0, "pending_commands": 0}
}
```

`online` 直接驱动平台的通讯状态显示和熔断的数据缺失率统计；`remote` 为 false（就地）时平台禁止向该站下发。

### 4.5 指令结果回调 `POST /api/ingest/commands/{command_id}/result`

网关在指令的每个状态变化时回调；拉取模式下也用这个接口回报。

```json
{
  "command_id": "CMD1A2B3C4D",
  "gateway_id": "GW-HS02-01",
  "status": "confirmed",
  "ts": "2026-11-03T10:00:09+08:00",
  "readback": {"ST08.pump_freq_sp": 43.0, "ST08.pump_freq": 42.6},
  "reason": ""
}
```

| status | 含义 |
|---|---|
| `accepted` | 网关已收到并通过签名、白名单、限值检查 |
| `written` | 已写入控制器 |
| `confirmed` | 回读到设定值已生效（终态，成功） |
| `rejected` | 网关拒绝：签名无效、过期、点位不在白名单、超出网关限值、就地状态（终态） |
| `failed` | 写入控制器失败（终态） |

### 4.6 点表下发 `GET /api/ingest/point-map?gateway_id=GW-HS02-01`

平台维护标准点位与现场位号的对应关系，网关启动时拉取，变更时按版本号更新。

```json
{
  "version": 12,
  "points": [
    {"tag": "ST07.ts2", "field_tag": "BY_HRZ.AI_T2G", "unit": "℃", "scale": 0.1, "offset": 0,
     "range": [0, 100], "rw": "r", "period_s": 5},
    {"tag": "ST07.pump_freq_sp", "field_tag": "BY_HRZ.AO_F1", "unit": "Hz", "scale": 0.01, "offset": 0,
     "range": [30, 50], "rw": "rw", "readback": "ST07.pump_freq"}
  ]
}
```

`rw = rw` 的点位就是网关的可写白名单。设计文档中的 `onboard_map_points`（新站点位自动映射）用于辅助生成这张表，目前尚未实现。

### 4.7 待执行指令（拉取模式）`GET /api/ingest/commands/pending?gateway_id=GW-HS02-01`

返回该网关待执行、未过期的指令列表，格式同 5.1。网关执行后用 4.5 回调结果。建议轮询间隔 2 秒。

## 5. SCADA / 采集网关需要提供的接口（平台调用）

基础路径示例 `https://{网关}/scada/v1`，双向 TLS。只有平台安全网关的证书可以调用写入接口。

### 5.1 指令写入 `POST /commands`

平台在审批令牌校验通过后下发。网关必须校验签名、有效期、点位白名单、网关自身限值和远程/就地状态，任一不满足即拒绝。

```json
{
  "command_id": "CMD1A2B3C4D",
  "station_id": "ST08",
  "writes": [{"tag": "ST08.pump_freq_sp", "value": 43.0}],
  "previous": [{"tag": "ST08.pump_freq_sp", "value": 45.0}],
  "issued_at": "2026-11-03T10:00:05+08:00",
  "expires_at": "2026-11-03T10:01:05+08:00",
  "approver": "李调度长（值班调度长）",
  "executed_by": "张调度（调度员）",
  "nonce": "5f1c9e0a7b",
  "signature": "base64(Ed25519(平台私钥, 上述字段的规范化 JSON))"
}
```

- `previous` 是下发前的设定，网关可以记录，用于本地复核。
- `signature`：平台安全网关用私钥签名（私钥由 KMS 托管），网关用平台公钥验证。即使网关的网络入口被冒用，没有私钥也写不进去。
- 曲线写入：`{"tag": "ST08.curve", "value": [[-26, 68], [-20, 63], [-15, 58], [-10, 53], [-5, 48], [0, 43], [5, 38], [10, 33]]}`。

响应：`202 Accepted` `{"accepted": true, "gateway_ref": "W-77812"}`。错误码：

| HTTP | code | 含义 |
|---|---|---|
| 401 | `BAD_SIGNATURE` | 签名无效 |
| 409 | `LOCAL_MODE` | 站点处于就地控制 |
| 409 | `DUPLICATE` | command_id 已处理过（防重放） |
| 410 | `EXPIRED` | 已过有效期 |
| 422 | `OUT_OF_RANGE` / `NOT_WRITABLE` | 超出网关限值 / 点位不在白名单 |
| 503 | `DEVICE_OFFLINE` | 与控制器通讯中断 |

### 5.2 指令状态查询 `GET /commands/{command_id}`

返回与 4.5 相同的结构。平台在没有收到回调时用它查询，避免重复下发。


## 6. 控制指令下发时序与失败处理

```
调度员/智能体      平台（调控链路）             平台安全网关            SCADA/网关              PLC
    │ 草拟、安全校验  │                            │                      │                      │
    │──────────────►│ 校验：限值/变化率/频次/联锁/   │                      │                      │
    │               │ 仿真验证/熔断/远程状态         │                      │                      │
    │ 提交审批        │                            │                      │                      │
    │──────────────►│ 值班调度长批准 → 签发令牌       │                      │                      │
    │ 凭令牌下发      │                            │                      │                      │
    │──────────────►│ 验令牌（一次性）──────────────►│ 回读当前值 5.3 ──────►│                      │
    │               │                            │ 签名指令 5.1 ────────►│ 校验签名/白名单/限值     │
    │               │                            │                      │ 写入 ────────────────►│
    │               │                            │                      │ 回读 ◄────────────────│
    │               │ ◄──── 结果回调 4.5（confirmed）─────────────────────│                      │
    │ ◄─────────────│ 指令状态：已执行；开始效果跟踪    │                      │                      │
    │               │ 效果偏离 → 回滚 = 以 previous 值重新走同一路径（同样需要签名与回读）            │
```

**超时与失败处理**

| 情况 | 平台处理 |
|---|---|
| 60 秒内未收到 `confirmed` | 指令标为“未确认”，产生二级报警，用 5.2 查询状态；**不自动重发**，由人工判断 |
| `rejected` / `failed` | 指令标为失败，记录原因，不改变平台记录的当前设定 |
| 回读值与设定不一致 | 标为失败并报警（可能被就地修改或控制器限幅） |
| 下发后通讯中断 | 现场保持设定；平台效果跟踪暂停；中断计入熔断的数据缺失率 |
| 同一管网频繁回滚 | 平台熔断，管网降为 L1（`backend/app/services/breaker.py`） |
| 就地/远程切换 | 网关通过 4.3 事件和 4.4 心跳上报；就地状态下平台拒绝下发 |

**与现有代码的差别**：当前 `ControlService.execute()` 同步完成，用仿真时延生成回执，并直接修改仿真器状态。对接后需要改成异步状态机：下发中 → 已执行（confirmed）/ 失败 / 未确认。

## 8. 安全要求

- **网络分区**：网关部署在生产控制网与管理网的边界。采集通道可经单向网闸；控制通道只开放安全网关到网关的单一路径（推送模式）或网关到平台的单一路径（拉取模式）。参照网络安全等级保护 2.0 和 IEC 62443 的要求做区域与通道划分。
- **双向 TLS**：网关与平台互相校验证书；证书按网关颁发，可单独吊销。
- **指令签名与防重放**：每条指令带 `command_id`、`nonce`、`expires_at`（建议 60 秒），由安全网关用私钥签名，网关验签并记录已处理的 `command_id`。
- **网关自身防护**：可写点位白名单、网关侧限值、写入频率限制、就地状态拒写。
- **最小权限**：网关服务账号只有 `ingest:write`；人工和智能体都没有这项权限；网关只能写自己负责的对象。
- **双方审计**：平台记录谁草拟、谁批准、谁下发、网关回执；网关记录收到的指令、验签结果、写入值和回读值。两边按 `command_id` 可以对账。
- **PLC 本地保护不变**：超温、超压、防冻、泵连锁等保护由 PLC 负责，平台指令不能绕过。

## 9. 数据质量要求

| 项目 | 要求 |
|---|---|
| 完整率 | 每站必需点位的有效数据（`quality = good`）占比 ≥ 99% |
| 时效 | 从现场采样到平台入库 ≤ 10 秒 |
| 时钟 | 网关与平台时钟偏差 ≤ 1 秒 |
| 单位 | 按第 3 节的单位上报，换算由网关或点表 `scale` / `offset` 完成 |
| 一致性 | 物理关系合理：供水温度 ≥ 回水温度；一次热功率 ≈ 流量 × 温差 × 比热；阀位在 0–100%；累计量不倒退 |
| 室温采集 | 每站采集点覆盖顶层、底层、边户、中间户，远离暖气片和窗户（知识库 POL-02 §2） |

设计文档中的 `onboard_check_data_quality`（接入后数据质量体检：缺失率、跳变、量程异常、物理矛盾）可以把上面的检查自动化，目前尚未实现。

## 10. 实施步骤与验收标准

| 阶段 | 内容 | 验收 |
|---|---|---|
| 1. 点表梳理 | 逐站核对现场位号、单位、量程、读写属性，编制点表（4.6）；补齐室温采集器 | 必需点位齐全，点表经双方确认 |
| 2. 网关部署与网络打通 | 部署网关，配置证书、防火墙、网闸 | 心跳正常，时钟偏差 ≤ 1 秒 |
| 3. 只读影子运行（建议 2–4 周） | 只采集不下发；平台报警、统计、AI 用真实数据运行；用历史数据校准机理模型参数；历史补传至少一个采暖季 | 完整率 ≥ 99%，时效 ≤ 10 秒；仿真验证对实测的稳态室温误差在可接受范围内（建议 ≤ 1 ℃） |
| 4. 控制联调 | 选 1–2 个测试站（或备用设备），逐项测试写入、回读、超时、就地拒写、签名错误拒写、回滚 | 每种控制点写入→回读一致；所有拒绝场景按预期返回错误；回滚成功 |
| 5. 小范围上线 | 试点站全部设为 L1，所有指令人工审批；熔断阈值按试点数据校准 | 指令确认时间 ≤ 30 秒；双方审计可按 command_id 对账 |
| 6. 逐步扩大 | 按站评估后把条件成熟的站提升到 L2/L3 | 回滚率、室温达标率、能耗等指标不劣于人工运行 |

上线前需要关闭演示能力：设置 `HEATNET_DEMO=0`、固定 `HEATNET_SECRET`（或改用 KMS），并移除仿真数据源。
